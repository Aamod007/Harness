## Problem Statement

Enterprise analytics consulting teams face messy, fragmented, and chaotic real-world telemetry when serving corporate clients. In Track 2 (Cybersecurity: Zero-Trust Telemetry & Insider Threat Logs), an enterprise cyber-command center must detect compromised accounts and insider threats across noisy, incomplete datasets:
1. Millions of firewall log records containing truncated IPv4 addresses, unparsed byte units, and unlinked session identifiers.
2. IAM audit trails with multi-format timestamps, mismatched session IDs, and fractional risk scores.
3. EDR endpoint alerts with unstructured vendor strings bundling severity, hostname, and malware signature.
4. Corporate identity asset master tables with inconsistent employee IDs and fragmented department names.

Conventional data engineering pipelines drop rows that fail validation, creating blind spots that adversaries exploit during credential stuffing, lateral movement, and data exfiltration. The challenge requires a 4-layer consulting delivery:
- Layer 1 (Data Rescue): 100% row survival with deterministic repair of broken records.
- Layer 2 (Analytics Layer): Certified, query-ready DuckDB data models defining mathematical risk metrics.
- Layer 3 (Executive Dashboard): Interactive, story-driven SOC workbench with zero-latency filters.
- Layer 4 (Agentic Graph AI): Natural language Text-to-Chart copilot generating dynamic Plotly visualizations and executive summaries.

Evaluations enforce a strict 4-stage Knockout gate: Gate 1 (Sanity/Compliance, 10+10 bonus pts), Gate 2 (Data Rescue, 30+10 bonus pts), Gate 3 (Dashboard, 40+10 bonus pts), Gate 4 (AI Excellence & Bonus, 30+30 bonus pts) for a maximum score of 170 points.

## What Makes This Cool

The "whoa" factor is the unbroken chain of custody from raw corrupted packets to instant natural language charts:
1. **Zero Data Loss Guarantee**: Ingests all 62,430 raw records across 4 heterogeneous files and cleans 100.0% of them without dropping a single row, verified by a cryptographic SHA-256 integrity receipt.
2. **Sub-5ms Columnar Analytics**: Embedded DuckDB materializes certified security views with zero formula drift between dashboard filters and AI copilot answers.
3. **Natural Language Text-to-Chart Copilot**: The user types queries like `"Show the trend of failed login attempts by department over the last 7 days"`, and the agent dynamically compiles the intent to SQL, selects the correct visual archetype (temporal Line, categorical Bar, or correlation Scatter), and renders an interactive Plotly chart with an executive summary.
4. **Dual-Mode SOC Workbench**: Runs seamlessly as a lightweight local web dashboard on port 8080 or inside an Electron desktop command shell.

## Constraints

- **Strict Knockout Rubric**: Evaluators stop immediately if any gate fails (missing public repo, missing README, missing data dictionary, missing cleaning proof, dropped rows, static dashboard).
- **Zero Paid Cloud Dependencies**: System must run locally on developer hardware or free tiers with zero API credit requirements.
- **Single-Command Execution**: Top-to-bottom reproducibility for evaluators via `npm start` or `python pipeline.py`.

## Premises

1. **100% Row Survival is Non-Negotiable**: In zero-trust security, dropping malformed records creates blind spots. Truncated IPs, missing sessions, and unstructured text must be reconstructed with explicit raw vs. clean audit logs.
2. **DuckDB Columnar Layer Guarantees Zero Disagreement**: Pre-materializing certified views (`v_dept_login_failure_trend`, `v_failed_login_rate`, `v_insider_risk_score`, etc.) in embedded DuckDB eliminates formula drift between dashboard cards and agent responses.
3. **Graph-First AI Combines Intent Classification, Dynamic SQL, and Plotly**: The agent must intelligently select chart types (Bar, Line, Scatter), render interactive plots, and provide executive text summaries.
4. **Reproducibility Trumps Complexity**: Single-command startup, local fallback capability, and a self-written, human-crafted README.md securing the 10-point Gate 1 bonus.

## Approaches Considered

### Approach A: Integrated Hybrid SOC Platform (DuckDB + Node.js + Plotly + Graph Copilot)
- **Summary**: Full-stack Node.js + DuckDB + Electron/Browser workbench with native Plotly rendering. It embeds the deterministic Python data rescue engine to generate certified DuckDB views, paired with a streaming Graph AI Copilot in `server.js` that compiles natural language into DuckDB SQL queries and returns typed Plotly JSON specs.
- **Effort**: Medium (human: ~2 days / CC: ~25 min)
- **Risk**: Low
- **Pros**: Captures maximum points across all 4 gates (170/170 pts); sub-5ms DuckDB queries; zero external database setup; dual-mode Electron & web delivery.
- **Cons**: Requires keeping Python data rescue script and Node.js server in sync.
- **Reuses**: Existing `data/cyber_metrics.duckdb`, `client/index.html`, `client/app.js`, `server.js`, `docs/CLEANING_REPORT.txt`.

### Approach B: Pure Python Streamlit + DuckDB Monolith
- **Summary**: Consolidates the entire solution into a multi-page Streamlit application and Jupyter cleaning notebook.
- **Effort**: Small (human: ~1 day / CC: ~15 min)
- **Risk**: Medium (Streamlit rerenders cause interface latency; loses Gate 3 innovation bonus)
- **Pros**: Single language Python stack; familiar to academic reviewers.
- **Cons**: Misses 10-point Gate 3 innovation bonus; lacks desktop shell and streaming thought chains.
- **Reuses**: `data/cyber_metrics.duckdb`, `docs/cleaning_report.ipynb`.

### Approach C: Multi-Agent Graph Dispatcher with Attack-Graph Blast Radius
- **Summary**: Multi-agent security investigation console running distributed agents (Data Engineer, Threat Analyst, Visualizer) with automated blast-radius graph generation.
- **Effort**: Large (human: ~4 days / CC: ~45 min)
- **Risk**: High (Agent non-determinism and timeout risks during fast evaluator grading)
- **Pros**: High novelty factor for AI evaluators.
- **Cons**: Complex orchestration risks failing basic Gate 2 or Gate 3 requirements if agents hallucinate.
- **Reuses**: Agent prompts in `.harness/`.

## Recommended Approach

**Selected: Approach A (Integrated Hybrid SOC Platform)**

Rationale: Approach A delivers the maximum competitive advantage. It satisfies every item in the stage-gate knockout rubric while providing an enterprise-grade experience. By grounding all analytics in DuckDB columnar views, the dashboard and Graph AI copilot deliver instant, deterministic results without cloud API expenses or slow re-renders.

### Architecture Specification:
1. **Tier 1 & 2 (Data Rescue & Storage)**:
   - File: `agents/pipeline.py` (and standalone `docs/cleaning_report.ipynb`)
   - Inputs: 4 raw telemetry files in `data/` (62,430 rows total).
   - Rescue Heuristics: Truncated IP completion, temporal IAM session reconciliation (+/-5 min window), unstructured AV alert regex parsing, multi-format timestamp conversion to ISO-8601 UTC, and department string normalization.
   - Output: `data/cyber_metrics.duckdb` with 5 canonical base tables and 5 certified views (`v_dept_login_failure_trend`, `v_failed_login_rate`, `v_insider_risk_score`, `v_firewall_action_by_protocol`, `v_endpoint_alerts_by_severity`).
   - Audit: Verification script logging raw vs clean row counts (100.0% survival) and SHA-256 hash digest.
2. **Tier 3 (Server & API Layer)**:
   - File: `server.js` (Port 8080)
   - Endpoints:
     - `GET /api/metrics`: Returns core KPI card counts and DuckDB health status.
     - `GET /api/views/:viewName`: Streams certified view rows to client.
     - `POST /api/copilot/query`: Accepts natural language query, maps to DuckDB SQL, executes query, determines chart archetype (Line, Bar, Scatter), and returns Plotly JSON + Markdown summary.
3. **Tier 4 (Presentation & SOC Workbench)**:
   - Files: `client/index.html`, `client/app.js`, `client/style.css`, `main.js` (Electron)
   - Layout:
     - Top Bar: Zero-Trust Telemetry Status, 100% Row Survival Badge, DuckDB Columnar Engine Health.
     - KPI Section: 4 Certified Metric Cards (Total Ingested Events: 62,430, Row Survival: 100%, High-Risk Insiders, Critical EDR Alerts).
     - Visual Center: Interactive Plotly Charts with filter dropdowns (Department, Protocol, Severity, Time Window).
     - Copilot Console: Natural Language Text-to-Chart input bar with quick-prompts (including required query `"Show the trend of failed login attempts by department over the last 7 days"`).
